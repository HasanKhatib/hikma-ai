# E7.8 - One form per menu task

## Goal

Each menu task is one `huh` form with groups, so Shift-Tab goes back a step and the answers already given survive a cancel. Today every question is its own short program, so stepping back means starting the task again.

## Context

Raised by the second review of the menu (2026-10-20), by the Bubble Tea reviewer, who called it a later epic and not a blocker. The cheap part was done in E7.7 instead: a mistyped registry asks for another one and keeps the agent.

The catch: `Prompter` asks one question at a time (`Select`, `Input`, `Confirm`, `MultiSelect`, `Spinner`), and the fakes in the tests drive exactly that. A multi-group form means the interface becomes "run this plan of steps", and the fakes would script a plan instead of answering questions. That is an interface change that touches every call site, so the council comes first (T1).

Not in scope: a custom Bubble Tea model for the whole menu, or anything that takes over the terminal.

## Open

- Whether back-navigation inside a task is worth changing the `Prompter` contract for. Esc and Ctrl-C already go back to the menu from any step, and a registry typo is already forgiven. If that is enough in use, close this epic.
- How a plan-shaped `Prompter` is faked: a script of answers per step, or a recording of the plan the code built.

## Exit

The council has decided whether Prompter becomes run-this-plan, and every menu task keeps its answers when the user steps back, with the fakes able to drive it.
