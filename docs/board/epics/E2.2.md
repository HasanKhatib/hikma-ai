# E2.2 - Neutral scaffold templates

## Goal

Ship templates that work for general open-source and private projects.

## Template Principles

- Generated files should mention only the user's project, selected agent, configured registry, and local conventions.
- Claude-first scaffolding should not generate opencode files unless the user asks for them.
- Templates should explain how to install and update skills from the configured registry.
- The generated output should be safe to commit publicly by default.

## Exit Check

Generated files mention only the user's project, selected agent, and configured registry.

## Agent-Aware Init

The CLI supports several agents even though this repo is developed with Claude only. `hikma init` takes `--agent` or prompts, records the choice in project config, and installs skills and instructions into that agent's layout. Layouts live in one table so adding an agent is a data change.

## Agent Layout Verification (2026-10-09)

Checked against each tool's published docs:

- Claude Code reads project skills from `.claude/skills/<name>/SKILL.md` and `CLAUDE.md`.
- Codex scans `.agents/skills` from the working directory up to the repo root, and reads `AGENTS.md`.
- GitHub Copilot reads project skills from `.github/skills`, `.claude/skills`, or `.agents/skills`.
- OpenCode reads `.opencode/skills` and, for compatibility, `.claude/skills` and `.agents/skills`.

So `.agents/skills` is a valid shared location for Codex, Copilot, and OpenCode. Layouts live in one table in `internal/config/agents.go`; adding an agent with its own folder (for example Cursor) is a data change plus an optional template.

## Implemented

- `hikma init` takes `--agent a,b`, `--registry`, and repeatable `--skill`; it writes instruction files, `.hikma/config.json` (agents, registry), and installs skills into every selected agent's folder.
- `agents` is a config key (`HIKMA_AGENTS`); a project list wins over the personal `agent` default.
- `skill install` and `skill update <name>` act on every configured agent.
