# E3.3 - Release packaging

## Goal

Publish Hikma AI through normal open-source release channels.

## Scope

- Decide whether the first release uses GitHub Releases only or also package managers.
- Name released binaries `hikma`.
- Generate checksums automatically.
- Document install commands for macOS, Linux, and Windows.
- Run a dry release from a test tag before publishing v0.1.
- Add a global Homebrew path so users can install with `brew install hikma` or a documented tap command.

## Homebrew Direction

The first working path can be a personal tap, for example `hasankhatib/tap`, with a formula or cask generated by GoReleaser. A later improvement can move to a direct `brew install hikma` flow if the project qualifies for Homebrew core or another global distribution path.

## Exit Check

Users can install a released `hikma` binary from GitHub releases and documented package channels, with Homebrew tracked as a first-class install path.

## Version

First release is v0.1.0, published as a pre-release.

## Install Channels (2026-10-09)

Homebrew is the only package manager. Everything else, including Windows, uses an install script:

```bash
# authenticated or private
gh api -H "Accept: application/vnd.github.raw+json" repos/HasanKhatib/hikma-ai/contents/scripts/install.sh | bash
# public
curl -fsSL https://raw.githubusercontent.com/HasanKhatib/hikma-ai/main/scripts/install.sh | bash
```

On Windows the script runs under Git Bash (installed with Git for Windows). It detects OS and arch, downloads the matching release archive, verifies `checksums.txt`, installs to `~/.local/bin`, and prints a PATH hint. No Scoop, winget, or other package managers.
