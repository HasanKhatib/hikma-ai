# E7.3 - Menu and wizards

## Goal

Running bare `hikma` in a terminal opens a menu of the common tasks. Scripts and CI keep getting help text. The menu holds no logic of its own.

## Context

Shipped in the menu PR (#37), merged 2026-10-17:

- `Prompter` interface (`Select`, `Input`) with a survey implementation and a fake for tests.
- `hikma` with no arguments opens the menu only when stdin and stdout are both terminals. Entries: install, browse, update, verify, create, publish, set up a project, choose an agent, set a registry, install completion, check setup, Quit. Each runs the ordinary flag command through a fresh root command and prints `Equivalent command:` afterwards. Ctrl-C exits quietly, including inside the chosen command's own prompt. Names must be non-empty, one word, and not start with a dash, because they become command arguments.
- Tests: every entry resolves to a real subcommand, Quit runs nothing, cancel is quiet, command errors pass through, names with spaces are rejected, bare `hikma` prints help without a terminal.
- Menu docs are the "The menu" section of `docs/site/getting-started.md`; the separate guide was folded in by #40.

Principles (also in AGENTS.md, CLI Interaction Rules):

- Flags are the API and the wizard is a front end. Every path prints its equivalent command.
- Without a TTY nothing prompts.
- Nothing is written before the user has seen the target and confirmed; the underlying command keeps its own confirmation.
- Prompts go through `Prompter`.

Not in scope: a full-screen TUI (Non-Goals).

## Research and council (2026-10-17)

- **huh:** the v2 import path is `charm.land/huh/v2`. It exports `ErrUserAborted` (map to `errCancelled`), `WithAccessible(bool)` (drops the TUI for plain prompts, a fit for `TERM=dumb` and screen readers; timeouts are unsupported there), `NewSelect`, `NewMultiSelect`, `NewConfirm`, and `NewInput` with `Validate`. Its docs do not mention Windows, so the hand check in T9 is the gate. pkg.go.dev flags v2.0.3 (March 2026) as not the latest, so confirm the newest tag when starting T9.
- **clig.dev:** prompt only when stdin is a terminal; `--no-input` means no prompting, and a command that still needs input fails and names the flag to pass; honor `NO_COLOR` (non-empty), `TERM=dumb`, and offer `--no-color`.
- **Council:** order T10, T5 (with T11, on survey), T9, T6, then hand walks. T7 is deferred. Details are in E7.1.md.

## Council on the huh prompter, PR #45 (2026-10-17)

Run on the opt-in PR; decision confirmed by the human the same day.

- Architect, `approve`. Reversible and prompt-only, but about 25 new modules, and bubbletea v2 asks the terminal about its capabilities at start. Must-fix: T12 covers a terminal that answers no queries, and `--no-input` stays the way out.
- Shipper, `defer`. No user gains until the default flips, and T12 can test from the branch. Must-fix: merge once, with the flip.
- Critic, `trim`. Two libraries and a hidden `HIKMA_PROMPTS` switch is a promise that could stick; the binary grows from 8.4 MB to 11.9 MB and the build from about 100 to 203 packages. Worth cutting: survey and the switch, in the flip PR.
- Terminal User, `rough`. `--no-color` did not reach huh (4 colored lines against 1 for survey). Must-fix: honor `--no-color`, `NO_COLOR`, and `TERM=dumb`; walk Windows.

Decision: do not merge #45 as an opt-in step. Done: `--no-color` sets `NO_COLOR` for huh (4 colored lines to 0, checked in tmux), and #45 now is the single PR that makes huh the default and deletes survey and `HIKMA_PROMPTS`. Left for T12: the Windows walk and a terminal that answers no capability queries, then merge. Confidence: medium. Reopen if huh hangs or misrenders on the Windows console, or the binary size becomes a distribution problem.

## Exit

Every menu entry runs the same code as its flag command and prints it, all prompts go through the Prompter interface, and non-TTY runs print help.
