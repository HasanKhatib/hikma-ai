# E7.3 - Menu and wizards

## Goal

Running bare `hikma` in a terminal opens a menu of the common tasks. Scripts and CI keep getting help text. The menu holds no logic of its own.

## Context

Shipped in the menu PR (#37), merged 2026-10-17:

- `Prompter` interface (`Select`, `Input`) with a survey implementation and a fake for tests.
- `hikma` with no arguments opens the menu only when stdin and stdout are both terminals. Entries: install, browse, update, verify, create, publish, set up a project, choose an agent, set a registry, install completion, check setup, Quit. Each runs the ordinary flag command through a fresh root command and prints `Equivalent command:` afterwards. Ctrl-C exits quietly, including inside the chosen command's own prompt. Names must be non-empty, one word, and not start with a dash, because they become command arguments.
- Tests: every entry resolves to a real subcommand, Quit runs nothing, cancel is quiet, command errors pass through, names with spaces are rejected, bare `hikma` prints help without a terminal.
- Menu guide at `docs/site/guides/menu.md`.

Principles (also in AGENTS.md, CLI Interaction Rules):

- Flags are the API and the wizard is a front end. Every path prints its equivalent command.
- Without a TTY nothing prompts.
- Nothing is written before the user has seen the target and confirmed; the underlying command keeps its own confirmation.
- Prompts go through `Prompter`.

Not in scope: a full-screen TUI (Non-Goals).
