# E5.2 - Signed releases

## Goal

Distribution is Homebrew plus an install script. Both should let a user check that what they installed was built by this repository's release workflow. Homebrew ships as a formula, which removes the need for macOS notarization.

## Decided (2026-10-12)

- **Attestations, not cosign.** The release workflow attests the archives and `checksums.txt` with `actions/attest-build-provenance` (keyless, no secrets). Users verify with `gh attestation verify <archive> -R HasanKhatib/hikma-ai`. `install.sh` runs that when `gh` is installed and signed in, pinned to `release.yml` with `--signer-workflow`. A checksum only proves the file matches `checksums.txt`, which is published next to it; the attestation proves who built it.
- **Version gate.** Releases before v0.3.0 have no attestation, so `install.sh` resolves the tag (the latest release when none is pinned) and installs older releases on the checksum alone. A missing attestation on a v0.3.0-or-later release is a failure, never a skip, because that is what a swapped archive looks like. It skips, and says so, only when `gh` is missing or signed out; `HIKMA_REQUIRE_ATTESTATION=1` turns that into a failure.
- **Formula instead of cask.** A cask download is marked quarantined, and macOS kills an unnotarized binary (exit 137), which is why the cask had a `postflight` hook and a Homebrew 7 deprecation warning. A formula download is not quarantined. Tested on 2026-10-12 (Homebrew 7.0.9, Apple Silicon): a formula installing the v0.2.0 archive ran with no workaround. GoReleaser's own formula publisher (`brews`) is deprecated since v2.10, so `scripts/render-formula.sh` writes the formula from `checksums.txt` and the workflow pushes it to the tap with the existing deploy key and removes `Casks/hikma.rb` (a cask and formula with one name make `brew install hikma` ambiguous). Pre-release tags do not touch the tap.
- **Notarization is optional now.** Only people who download an archive in a browser benefit. The Apple Developer account is available. If the membership lapses, already notarized releases keep working and only new signing stops, so the plan is a conditional GoReleaser `notarize` step that runs when the secrets exist. See T3.

## Why the formula needs a real run

The attestation step, the signer-workflow pin, and the tap push can only be proven by a real tag. T5 cuts `v0.3.0-rc.1` for that. The rc builds and attests but skips the tap; render the formula from its `checksums.txt` and install it from a local tap to check it.

## User docs

User docs describe shipped behavior only, so the verification instructions and the cask-to-formula note for existing users go in at the tag (T6), not before.
