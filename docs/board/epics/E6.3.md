# E6.3 - Release v1.0

## Goal

Cut v1.0 only when the surfaces that scripts and teams depend on are frozen and documented, and a release candidate has been tried on macOS, Linux, and Windows.

## Why a release epic

v1.0 freezes config keys, the lockfile format, JSON output, exit codes, and the skill layout (E6.1). E6.2 proves they hold on all platforms. This epic is the last gate: docs match shipped behavior (AGENTS.md: user docs describe shipped behavior only), an rc is installed from the real channels, then the tag.

## Order

E6.1 and E6.2 first, then T1, T2, T3. T2 uses `v1.0.0-rc.1` the way v0.3.0 used `v0.3.0-rc.1`.

## Exit

`v1.0.0` is tagged after an rc, and the changelog and docs describe only shipped behavior.

## Docs audit, 2026-10-18 (T1)

Checked every command page against `--help`: every flag is documented or covered by the Reference pages, and every `hikma ...` example in the docs and README names a real command and real flags (scripted check). Added `hikma update` to the command index, linked the global flags and exit codes, refreshed the `doctor` sample, and moved the Action example to v0.5.0.

## Release candidate, 2026-10-18 (T2)

`v1.0.0-rc.1` was tagged from `main` after CI, Terminal, Completion, and Canary were green. Release and Verify release both succeeded (script install on Linux, macOS, and Windows, checksum and attestation required). Installed locally with the script into a scratch folder (attestation verified, `hikma version 1.0.0-rc.1`), then the round trip ran with that binary against the throwaway registry: create, push, install, verify, tamper (exit 3), bad flag (exit 2), upstream change, update, verify. Homebrew is not exercised for a prerelease because the tap only follows stable tags; the stable tag's Verify release run covers it.
