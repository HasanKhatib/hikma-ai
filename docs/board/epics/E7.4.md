# E7.4 - Completion install and push polish

## Goal

Three small improvements that shipped together in #35 and had no board entry: shell completion that installs itself, a publish step that takes one action when you own the registry, and error messages that tell you what to type.

## Context

Shipped in #35, merged 2026-10-17.

- **Completion.** `hikma completion` with no shell detects yours, shows the file it would change, and asks. `--install` does the same for a named shell and `--yes` skips the question. `hikma completion <shell>` still only prints the script. The installer skips when `hikma` is missing, ignores commented lines, and uses `.bash_profile` on macOS. The old zsh advice to write to `${fpath[1]}` is gone, and the Homebrew formula installs completions.
- **Push.** With write access `hikma skill push` commits straight to the registry's default branch. `--pr` keeps the pull request flow. Without write access it still forks and opens a pull request. A protected default branch gets an error that suggests `--pr`. The confirmation states which of the two will happen, and `--codeowners` requires `--pr`. Unfilled template placeholders are warnings, not failures, so a draft can be pushed for review.
- **Adopt and errors.** `hikma skill adopt` on a skill without `gh skill` metadata explains why and shows the commands to run. Mistyped arguments, commands, and flags name the problem, the usage line, and a likely fix.

## Open

- T7: only the unit tests and a macOS zsh run have exercised the installer. bash, fish, PowerShell, and Windows still need a hand check, including that a second run changes nothing.

## Council: the direct-push default (2026-10-18)

Decision: with write access, `skill push` commits straight to the registry's default branch, and `--pr` opts into review. It changed behavior for everyone with write access in #35 without a council run, so this is the review after the fact. Quick check, one paragraph per seat.

- Architect, `revise`. Reversible in practice: a direct commit is undone by a revert, nothing is force-pushed, and the confirmation says "no review" before anything is written. The gap is a registry whose default branch requires pull requests: the commit fails first and the user has to retry. Must-fix: look at the branch rules first and switch to a pull request on its own.
- Shipper, `ship`. The point of a registry you own is one step from skill to published. A config key to flip the default would be speculative.
- Critic, `keep`. Do not add a `push.mode` config key before 1.0; every key becomes a contract. The rules check is a few lines and replaces an error path.
- Terminal User, `smooth` with one note. `--yes` in CI commits straight to the default branch. The confirmation line prints which mode applies, so it shows in the job log. Must-fix: say in the docs that a script wanting review passes `--pr`.

Decision: keep the default. Done: `skill push` reads the default branch's rules (the rules endpoint, readable with push access) and opens a pull request by itself when they require one, saying why; the confirmation shows the same. Classic branch protection is not visible there, so a rejected commit still suggests `--pr`. The docs have an "In scripts and CI" note. Confidence: high. Reopen if registries with required reviews are common enough that people hit the classic-protection error, or if a user publishes unreviewed code by accident.

## Exit

hikma completion installs for bash, zsh, fish, and PowerShell and is verified on macOS, Linux, and Windows, and push, adopt, and error messages behave as documented.
