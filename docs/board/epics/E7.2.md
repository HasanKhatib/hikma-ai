# E7.2 - Brand and terminal look

## Goal

One logo, used the same way in the CLI, the docs site, and the README, and output that is colored on a terminal and plain everywhere else.

## Context

Shipped in the menu PR (#37), merged 2026-10-17:

- `internal/ui` color helpers: green, cyan, bold, dim, next to the existing yellow and red. All of them return plain text when the writer is not a terminal, under `NO_COLOR`, or with `TERM=dumb`.
- The CLI banner: the logo's frame and `>_` in box characters, a gradient from teal to blue (truecolor when `COLORTERM` says so, basic ANSI otherwise), with a "hikma" wordmark.
- Site: `docs/site/public/logo/` holds the logo and favicons. VitePress links the favicons, apple touch icon, and manifest, and the nav uses `Logo.png`. The manifest had an empty name and absolute icon paths; both are fixed. The README shows the logo.

Decided: the banner does not reproduce the Arabic calligraphy. Converting the PNG to braille art at 44 columns gave unreadable blobs, and Arabic shaping in terminals is unreliable. The Arabic stays on the site and README.

Windows: `vtSupported` turns on ANSI processing for the console handle and keeps color off where the console refuses it (T7). Compiled for Windows but not yet run on one; T5 covers that.

Site favicons: the old `favicon.svg` link is gone so browsers use the new icons; the old SVG files are still in `docs/site/public` until T8.

## Open

- T4: apply the helpers where output is plain today (doctor, list, verify). Color must never be the only carrier of meaning: keep the `ok` and `FAIL` words.
- T5: a human check on Windows PowerShell, the legacy console, and a light theme, where the gradient may be hard to read.
- T6: a social card for link previews.

## Exit

The logo appears in the CLI banner, docs site, favicons, manifest, and README, and color is verified on macOS, Linux, and Windows terminals with NO_COLOR respected.
