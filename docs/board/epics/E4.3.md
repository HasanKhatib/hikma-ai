# E4.3 - Custom agent layouts

## Goal

Agents are table entries in `internal/config/agents.go`. Instead of verifying and maintaining a long list of built-in agents, users define their own layout in config. Built-ins stay at the four verified agents (Claude, Codex, Copilot, OpenCode). Cursor and Gemini CLI are dropped (T1, T2): custom layouts cover them.

## Changed (2026-10-12)

The key is `layouts`, not `agents.<name>`: `agents` is already a config key holding the list of agent names (E2.2-T7).

```json
{
  "agents": ["claude", "acme"],
  "layouts": {
    "acme": { "skillsDir": ".acme/skills", "instructionFile": "ACME.md" }
  }
}
```

## Rules

- `skillsDir` and `instructionFile` are slash-separated and relative. No `..`, no absolute paths or drive letters, and nothing inside `.git` or `.hikma`.
- A layout name cannot reuse a built-in name.
- `skillsDir` is required; `instructionFile` is optional.
- The project config is committed, so a layout from a cloned repo must never be able to write outside the project. The same relative paths also work under `$HOME` for global installs (E4.2), so no extra field is needed.
- `sync` rejects lockfile entries outside the known skills folders (`layoutSkillDirs()` in `sync.go`). It must accept configured layouts, or `hikma sync` would refuse every custom-layout entry (T5).
- Multi-agent duplicates (T7): Copilot and OpenCode read both `.claude/skills` and `.agents/skills`, so `agents: claude,copilot` writes a skill to two folders one agent reads. The install proceeds and warns.
