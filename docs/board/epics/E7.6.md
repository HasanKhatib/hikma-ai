# E7.6 - Docs site and home page

## Goal

A short docs site that shows who built it, and a home page that explains Hikma in one screen: a pixel-art loop of a developer and a bot pet that walks through init, install, create and push, and sync.

## Context

Built across PRs #40 to #48 on 2026-10-17 and 2026-10-18; all are merged on main (#46 and #48 landed together on 2026-10-18).

- **#40** adds a floating "Developed by Hasan Alkhatib" credit (links to alkhatib.tech) and cuts the guides to three: Agents and folders, Skill format, and Run a registry. The five removed guides moved into the pages they belong to: global installs into Agents and folders, the lockfile into `sync`, team setup into `init`, the menu into Getting started, and `gh skill` into `skill adopt`.
- **#41** shows the real version in the nav (read from `CHANGELOG.md`, so it cannot go stale), a Copied check mark, a link to read the install script first, and darker muted text for contrast.
- **#42** adds the Taskfile. `task docs:preview` serves the production build under `/hikma-ai/` like GitHub Pages; `task docs:stop` only stops a vitepress server.
- **#46** replaces the install window in the hero with the pixel-art scene and a one-line install. **#48** slows it 1.6x, adds a title screen, four clickable stages, the bot changing color with its skills (dark, blue after `go-blue`, violet after `walking-above-holes`), and light and dark palettes.
- The scene is a pure function of time (`heroScene.ts`) drawn on a canvas, with real text for balloons and the CLI overlay. `?t=<seconds>` freezes a frame, which is how the stills were checked and how a video export would work.

## Lessons

- #41 was merged before the commit that removed its terminal demo had been pushed, so `main` carried a home page that scrolled until #46. When a PR changes after review, check the merge picked up the last commit.
- A hero that fills the screen cannot take a section below it without scrolling; the scene went into the hero instead, and the hero is tightened under 800px tall.
- Headless Chrome screenshots with `--virtual-time-budget` do not advance CSS transitions, so a stage button can look half-switched in a still. Disable transitions in the test copy.

## Open

- T7: the scene was only checked with headless frames. Real-time smoothness, clicking a stage, light mode on a real screen, and the phone layout are not checked.
- T8: no video export yet.

## Exit

The home page fits one screen on a laptop in light and dark mode, the scene and stage buttons are checked in a real browser, and the site builds with no dead links.
