# E7.5 - Release v0.5

## Goal

Ship v0.5 (Guided CLI). Everything in P7 lands on `feat/menu-council-brand`; this epic is the path from that branch to a tagged release.

## State on 2026-10-18

All P7 work is on `main` and green on Linux, macOS, and Windows. The hand walks became automated checks, so what is left before the tag is the tag itself.

- **Menu, prompts, color (E7.2-T5, E7.3-T8, E7.3-T12):** `e2e/` (the Terminal workflow, apart from `go test -short`) builds the binary and drives it on a pty (Linux, macOS) or ConPTY (Windows) that answers no terminal queries.
- **Completion (E7.4-T7):** the Completion workflow installs and runs it on bash, zsh, fish, and PowerShell on all three OSes and reruns the installer. It found a real bug (bash on Linux fell back to `.bash_profile`).
- **Home page (E7.6-T7):** the Docs e2e workflow runs Playwright in Chromium, Firefox, WebKit, and two phone profiles. It is manual only (Actions tab), because the docs build already fails on dead links on every PR. It found a real bug (the install command made phones scroll sideways).
- **Install checks (E7.5-T4):** the Verify release workflow installs a release with the script (checksum and attestation required) and Homebrew, runs a smoke test, and checks the version. It ran green on v0.4.0 for all three OSes.

## Release steps

1. `git tag v0.5.0 && git push origin v0.5.0`. The Release workflow builds, attests, publishes, and updates the Homebrew formula.
2. The Verify release workflow starts when Release succeeds. Open it from the Actions tab. If it fails, fix forward and re-run it with a tag input.
3. Optional, whenever convenient: look at the menu and colors in the Windows legacy console and a light terminal theme, and at the home page on a phone. Automation proves behavior, not looks.

## Exit

`v0.5.0` is tagged, `brew install` and the install script work on all three platforms (the Verify release run shows it), and the changelog has a 0.5.0 section.
