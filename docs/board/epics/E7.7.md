# E7.7 - Menu that stays open

## Goal

The menu is a wizard you stay in. It clears the screen, finishes a whole task (for example, installing several skills), shows one clear result, and goes back to the menu until you quit. It stays an inline, prompt-driven menu: nothing takes over the terminal.

## Context

On 2026-10-20 the owner ran bare `hikma`, picked "Install a skill", pressed Enter, and got `error: missing argument for 'hikma skill install'`. Cause: with a registry already set the menu planned `hikma skill install` with no skill name, and the command needs one (`cobra.RangeArgs(1, 2)`) even though its usage line shows `[<name>]` as optional. The menu also exited after one task and never cleared the terminal. This is the "user demand" that reopens **E7.3-T7** (menu looping, deferred by the council on 2026-10-17 so runs stay scriptable). This epic tracks it; the owner closes T7.

### Already built (uncommitted on `main` at the time of writing, 2026-10-20)

- `runWizard` loops: clear, banner, menu, run, show the error if any, print the equivalent command, then "What next?" (Back to the menu or Quit). Ctrl-C inside an entry returns to the menu; Ctrl-C at the menu leaves. A failed task shows its error and does not close the menu.
- `collectInstall` asks for the registry and agent only when unset, fetches the skill list (`registrySkills`, a variable so tests do not clone), lets the user tick several skills, and plans one `skill install [<owner/repo>] <name> [--agent a]` per skill. Names that start with a dash are dropped from the picker because they would be read as flags.
- `ui.ClearScreen` (terminal only, not `TERM=dumb`), a test that every planned command passes its own command's argument check, and an e2e that clears, returns to the menu, and quits.
- Audit result: of the 11 menu entries only install planned an invalid command. Completion asks for its shell itself in a terminal.

### Not in scope

- A full-screen or alt-screen TUI, screen stacks, panes, a command palette, mouse capture (Non-Goals in AGENTS.md). See "Where the rule costs something" below.
- Changing what any command does when run with flags. Flags stay the API; the menu is a front end.

## The review meeting (2026-10-20)

Two specialists reviewed the code by reading it, then answered each other: one from the Bubble Tea and Charm school (huh, bubbles, gum), one from the Textual and Rich school. Neither ran the binary, so every claim below that is marked "verify" must be checked while building.

### What both agreed on

1. Keep the `Prompter` seam; it is the best decision in the design.
2. Stay inline. No custom Bubble Tea model for the whole menu, no alt-screen.
3. **The one tool: stay on `charm.land/huh/v2` and add `huh/spinner`.** The module cache and `go.mod` already carry Bubble Tea v2 and bubbles v2 as indirect requirements, so this adds no new module, only a promotion to direct. A second prompt library would add a second terminal stack and discard the theme and accessible-mode work. The Textual specialist looked for something better and found nothing in Go that earns its cost; Textual itself is Python and cannot be embedded.
4. Fix before polish: scrollback wipe, Ctrl-C during the fetch, the one-clone-per-skill waste, list height.
5. Meaning never rides on color alone: every state has a symbol or a word.

### Concessions

- Textual dropped its "Retry failed" menu item as a standing entry; Bubble Tea dropped "press enter to return" and its custom fetch-and-picker model, and demoted the multi-group Shift-Tab form to a stretch task.

### Disagreements and how this plan resolves them

| Question | Bubble Tea | Textual | Plan |
| --- | --- | --- | --- |
| Installed skills in the picker | Disabled rows | Selectable, marked "will update" | Selectable, marked (T7). huh has no disabled option, and reinstalling must stay possible. |
| "What next?" | Keep, with Retry | Plain return | Keep it; show "Retry failed" only when something failed (T8). |
| Hints on every error | Only where the cause is known | Always a "try this" | Only where known: no registry, not found, no sign-in (T9). Generic hints are noise. |
| Preview pane | Maybe, as an inline picker | About 10% value | Not now. One line of description under the cursor. |
| Combined equivalent command | Only if it is real | Show it last | Show it last, and only after T6 makes it a real command. |

### Where the rule costs something

Both specialists said browsing a registry (filter, detail, installed marks at once) wants a persistent layout. This plan does not break the rule. If the owner wants an inline multi-line picker with a preview, that is a rule change and a council question; it is not assumed here.

## Decisions to take first (T1, council)

AGENTS.md requires the council for new dependencies and CLI contract changes, and 1.x is stable.

1. **Several skills from one checkout.** Listing clones the registry once and each `skill install` clones again: 5 skills cost 6 clones, and the printed commands are five lines, not one. Options:
   - **A. Variadic names:** `hikma skill install owner/repo foo bar baz`. Additive, but ambiguous with today's `[<owner/repo>] [<name>]` when two arguments are given (two names, or a source and a name?). Needs a rule such as "the first argument is a source if it looks like one" (already `source.LooksLikeSource`), and a documented tie-break.
   - **B. Repeatable flag:** `hikma skill install owner/repo --skill foo --skill bar` (`init` already has `--skill`). No ambiguity, additive.
   - **C. Wizard only:** an in-process helper that opens the source once; the menu prints N commands. No contract change, but the "one command" is not real and costs the scripting story.
   Recommendation to the council: **B**, because it cannot be misread and reuses an existing flag name.
2. **Dependencies:** promote `charm.land/huh/v2/spinner` (and bubbles if needed) to direct. Check binary size against the 8.4 to 11.9 MB history in E7.3.
3. **Prompter additions:** `Spinner`, and options on `MultiSelect`/`Select`. Interface changes touch every fake; keep them small.

## Built (2026-10-20, one PR on `feat/wizard-stays-open`)

T1 to T9 and T11 are built. T10 is not, and T12 is yours.

- **T1, council (quick check).** Architect `approve`, Shipper `trim`, Critic `keep`, Terminal User `rough`. Decision: option B, a repeatable `--skill` on `skill install`, additive and with no ambiguity against `[<owner/repo>] [<name>]`. `charm.land/huh/v2/spinner` is inside the huh module already used; `bubbletea/v2` and `charmbracelet/x/term` moved from indirect to direct at the same versions, with no new module and an unchanged `go.sum`. Confidence medium: Windows is unchecked. Reopen if `--skill` collides with `gh skill`.
- **Deviation from the plan, T7.** The meeting resolved installed skills as "selectable, marked will update". Building it showed `skill install` refuses an installed skill without `--force`, and `--force` replaces local edits, which AGENTS.md forbids doing silently. So installed skills could not be selectable. First they were named above the picker and left out of it; on 2026-10-20 the owner asked to see them in the list, so they are now listed last, crossed out where the terminal can show it and always marked `[installed]`. huh has no disabled option, so a tick on one is ignored and the picker is shown again if nothing else was ticked. When every skill is installed, the menu shows a notice (not an `error:`) with the list and the Update command. Reopen if people want a reinstall from the menu; it would need its own confirmation.
- **Prompter.** Gained `Spinner(message, fn)` only. Filtering, height clamping, and key hints are done inside the huh implementation, so no fake needed new options. Select filters on `/` (huh's default); MultiSelect filters above 8 options and `ctrl+a` ticks all.
- **One checkout.** A single `skill install --skill a --skill b` opens the source once. The menu still reads the registry once to list it and the command reads it once more to install: two reads, down from one per skill plus one.
- **Checked by tests, not by hand (2026-10-20).** The pty e2e runs on Linux, macOS, and Windows (ConPTY) in CI: the menu loop and Esc, a real install through the menu, accessible mode (numbered prompts, no screen clear), and, on Unix, Ctrl-C during a clone that hangs (a fake `git` on PATH): the menu comes back and the `git` process is gone. The Ctrl-C test fails if the cancellation is removed. **Still not judged by a person:** how the menu looks in the Windows legacy console and a light theme, and a real screen reader. Cancelling the spinner stops waiting, but the `git` clone behind it finishes in the background and cleans up after itself; plumbing a context into `internal/source` would stop it, and was left out to keep this change inside the menu. Accessible mode (`ACCESSIBLE=1`) is covered by unit tests, not by a screen reader. How it looks in the Windows legacy console and a light theme is T12.

## Second review (2026-10-20): what was fixed and what was not

Two reviewers (Bubble Tea and Textualize) read the first PR. They agreed on five points and each raised others. All of the following were fixed in the same PR (T13):

- **Ctrl-C and work with no child process.** `signal.Notify` swallowed the interrupt for the whole run, so a file copy kept going. Now `withInterrupt` hands the work a context that Ctrl-C cancels (`signal.NotifyContext`), the menu runs the command with `ExecuteContext`, `skill install --skill` checks it between skills and reports the rest as "not started: cancelled", and a second Ctrl-C restores the default and ends hikma.
- **Cancelling the spinner did not cancel the work, and the work raced.** The clone now takes the context (`source.ResolveContext`, `exec.CommandContext`), and the fetch reports through a buffered channel instead of shared variables, so an abandoned spinner cannot race with the caller. Checked under `-race`; I did not run the new test against the old code to see it fail.
- **Ctrl-C at "What next?" quit hikma**, against the banner. It now goes back to the menu. Esc does the same wherever the list cannot be filtered (huh checks the form's quit key before the field, so Esc on a filterable list would otherwise skip clearing the filter).
- **A skill installed for one agent was hidden from the others.** The filter is per target agent, and a failure to list installed skills is now returned, not dropped.
- **A mistyped registry lost the other answers**, and declining the plan said nothing. A bad registry now asks for another one and keeps the agent; declining says "Nothing was installed."
- **Short terminals** overflowed under 12 rows; the list is now held to at least four rows.
- **Minor:** padding uses display width (`ui.Width`, `ui.Pad`, so accents and wide characters line up), the minimum error says how many to choose, a partial failure no longer repeats the summary in its error line, and it prints the command that ran plus the command that retries only the failures.
- **Polish:** the cursor stays on the entry last used, Esc is bound and shown as a hint, long registry names are shortened, the plan shows a description column, and accessible mode draws the banner once and asks for lists by number.

Not done, on purpose:

- **Retry does not add `--force`.** The Textualize reviewer noted that retry cannot fix "already installed". It must not: `--force` replaces local edits. The menu keeps installed skills out of the picker, so this only happens after a race or an install from outside the menu, and the result line says to use `--force`.
- **One form per task** (Shift-Tab back, answers kept) needs the `Prompter` contract to change. It is a later epic: E7.8, with the council first.
- **Still unchecked:** Windows (T12), and Ctrl-C while a command runs on a real pty with a slow clone (covered by a Unix unit test that sends a real SIGINT to a task with no child process).

## After first use (2026-10-20, T14)

The owner used the 1.2.0 menu and asked for changes, all built in the same PR:

- **Install:** installed skills are listed, crossed out and marked `[installed]`; all-installed is a notice, not an `error:`.
- **Create:** asks for a description (optional) and links a new guide, `guides/write-a-skill`, which cites Anthropic's and OpenAI's published guidance on descriptions, scripts, references, assets, and hooks. The links were fetched and read on 2026-10-20, and the OpenAI page had moved (`developers.openai.com/codex/skills` now redirects to `learn.chatgpt.com/docs/build-skills`), so the guide records the check date.
- **Publish:** reads the registry and marks local skills that already exist there with `[exists]`; an unreadable registry only means no marks.
- **Multi-select:** `[ ]` / `[x]` checkboxes, through one theme for every multi-select.
- **Other commands reviewed for the same patterns:** `skill list` and the `skill install` picker mark `[installed]`. Not changed, on purpose: the `skill import` picker lists a *source's* skills, and marking which exist in the registry would need a second registry read before the choice; `--json` output carries no display markers.
- **Completion:** `hikma completion` said "already set up" while completion did nothing in the owner's open window. The line itself was fine (checked in a fresh interactive zsh: `compdef` present, `_hikma` registered, `hikma __complete` answering). It only applies to windows opened after the line was added, so the message now says so and gives `source <rc>`; for zsh it also warns when `compinit` is not before the hikma line (verified: that order prints `command not found: compdef`).
- **Two bugs found on the way:** a quote or backslash in a skill description broke the `SKILL.md` frontmatter (escaped now), and the prompt refused an empty answer before the caller's validator ran, so "leave empty" questions could not be left empty in a terminal.

## Tasks and acceptance criteria

PR order is T2, T3, T4, T5, then T1 gates T6, then T7 to T9. One PR each; `task ci` before every PR.

### T2: Terminal hygiene (S)

- `ClearScreen` writes `"\x1b[H\x1b[2J"` only, and returns early in accessible mode (`ACCESSIBLE` set or `TERM=dumb`). Today it also sends `\x1b[3J`, which erases the user's scrollback (`internal/ui/color.go`, written 2026-10-20).
- `applyNoColor` no longer calls `os.Setenv` on every prompt (`prompter_huh.go`). Build the theme once from `ui.NoColor`.
- Done when: `color_test.go` asserts the sequence has no `3J`; a test shows accessible mode writes nothing; no env var changes during a prompt.

### T3: Picker usability (S)

```go
type SelectOpt func(*selectCfg)
func Filterable() SelectOpt
func MaxHeight(rows int) SelectOpt

MultiSelect(message string, options []string, defaults []int, min int, opts ...SelectOpt) ([]int, error)
```

- huh side: `.Filterable(true).Height(min(len(options)+2, termRows-8))`; terminal rows from `golang.org/x/term` or `charmbracelet/x/term` (already indirect).
- Clamp `Select` the same way. Filter on lists of more than 8 items. Add select-all (verify what key huh gives; document it in the hint).
- Hint under each menu: `enter select · / filter · ctrl+c back`.
- Done when: a pty test at 24 rows with 60 options never draws more rows than the terminal has.

### T4: Spinner (S)

```go
// Prompter
Spinner(message string, fn func(ctx context.Context) error) error
```

- huh: `spinner.New().Title(message).ActionWithErr(fn)`. Fake: calls `fn`. Without a terminal or in accessible mode: print `message` once, run `fn`.
- Wrap `registrySkills` in `collectInstall`: `Reading acme/skills...`.
- Done when: the e2e sees the title, then the picker; the fake test shows `fn` ran exactly once.

### T5: Ctrl-C returns to the menu (M)

- Today no tea program runs during the fetch or the command, so Ctrl-C is a raw SIGINT and hikma exits (verify with a slow fake fetch). Wrap each action in `signal.NotifyContext(ctx, os.Interrupt)` and map cancellation to `errCancelled`, which already means "back to the menu".
- Pass `ctx` into `registrySkills`; cancel the git process through it.
- Done when: an e2e sends Ctrl-C during a slow fetch and the menu is drawn again; the repo's cancel-is-quiet test still passes. Check the Windows ConPTY path (T12).

### T6: One checkout for several skills (M, after T1)

- Implement the T1 decision. Acceptance: a fake-GitHub test counts exactly one clone for five skills; the printed equivalent command is one line that a user can paste and get the same result.

### T11: Docs and tests, per PR

- Every PR updates `docs/site/getting-started.md` (The menu), the README, and `CHANGELOG.md`, and adds its e2e.

### T12: Hand check (me)

- Windows PowerShell and the legacy console (clear, scrollback, spinner, VT), macOS Terminal and iTerm, a light theme, an 80-column window, and a screen reader with `ACCESSIBLE=1`. The automated checks prove behavior, not looks.

## Risks

- Interface changes to `Prompter` touch every fake and every call site; keep each addition optional.
- Spinner animation makes pty tests flaky: assert on final text, never on frames.
- A wrong `Height` (the terminal reports 0 rows when it cannot be queried) must fall back to the current behavior, not to a tiny list.
- Ctrl-C handling differs on Windows ConPTY; T5 is not done until T12 passes there.

## Exit

Every menu task runs end to end with a spinner, a plan, a one-screen result, and the equivalent command last; Ctrl-C never kills the menu; a pty test passes on Linux, macOS, and Windows.
